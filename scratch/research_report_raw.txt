## 7. OWASP Top 10 for LLM Applications 2025

**Status:** Finalized, widely adopted as baseline for AI security threat modeling, SOC 2 audits, and compliance

| ID | Risk | Description |
|---|---|---|
| LLM01 | **Prompt Injection** | Direct & indirect manipulation of model behavior via malicious inputs |
| LLM02 | **Sensitive Information Disclosure** | PII, credentials, proprietary data exposed in outputs |
| LLM03 | **Supply Chain Vulnerabilities** | Risks from third-party datasets, plugins, models, software |
| LLM04 | **Data and Model Poisoning** | Manipulation of training/embedding data to introduce backdoors |
| LLM05 | **Improper Output Handling** | Failure to validate outputs → downstream injection or RCE |
| LLM06 | **Excessive Agency** | Too much autonomy/permissions → damaging unauthorized actions |
| LLM07 | **System Prompt Leakage** *(NEW)* | Unauthorized extraction of internal instructions/system logic |
| LLM08 | **Vector and Embedding Weaknesses** *(NEW)* | RAG pipeline flaws → injection or leakage via compromised vector stores |
| LLM09 | **Misinformation** | False/misleading content generation that users over-trust |
| LLM10 | **Unbounded Consumption** | Denial-of-service or runaway costs from uncontrolled resource usage |

**Key changes vs. 2023 version:** Added LLM07 (System Prompt Leakage) and LLM08 (Vector/Embedding Weaknesses); stronger agentic AI focus throughout; reordering to reflect real-world incident frequency

**Use in tandem with** OWASP LLM Top 10 (which covers model-level risks)

| ID | Risk | Description |
|---|---|---|
| ASI01 | **Agent Goal Hijack** | Attacker manipulates agent to change primary goal / follow hidden instructions |
| ASI02 | **Tool Misuse & Exploitation** | Agent uses legitimate tools (APIs, DBs) in unsafe/unintended ways → data exfiltration |
| ASI03 | **Identity & Privilege Abuse** | Agent uses excessive permissions or stale/insecure credentials for unauthorized actions |
| ASI04 | **Agentic Supply Chain Vulnerabilities** | Malicious/compromised third-party agents, tools, or prompt templates |
| ASI05 | **Unexpected Code Execution** | Agent generates and executes malicious commands → server/system takeover |
| ASI06 | **Memory & Context Poisoning** | Malicious data planted in agent's long-term memory → influences future decisions |
| ASI07 | **Insecure Inter-Agent Communication** | Agent-to-agent exchanges lack auth/integrity checks → interception/spoofing |
| ASI08 | **Cascading Failures** | Single vulnerability propagates across autonomous agent networks → system-wide impact |
| ASI09 | **Human-Agent Trust Exploitation** | Anthropomorphic manipulation of human users into unsafe actions |
| ASI10 | **Rogue Agents** | Compromised agents deviating from scope to act harmfully or pursue hidden goals |

## 11. MCP (Model Context Protocol) — Adoption & Security Research 2026

### Adoption Scale
- **97 million+ monthly SDK downloads**
- **Thousands of public MCP servers**
- Native support from: Anthropic, OpenAI, Google, Microsoft
- **Governance:** December 2025 — Anthropic donated MCP to the **Agentic AI Foundation (AAIF)** under Linux Foundation (vendor-neutral governance)

### Security Vulnerability Classes Discovered

| Vulnerability | Severity | Description |
|---|---|---|
| **Prompt Injection via Tool Metadata** | Critical | Malicious prompts in tool descriptions/metadata subvert security controls |
| **Arbitrary Code Execution (ACE)** | High | Insufficiently secured MCP servers → CWE-77, 78, 94, 95 |
| **Confused Deputy Problem** | High | Server executes actions with elevated privileges vs user's actual permissions |
| **Supply Chain Risks** | High | Malicious MCP packages on PyPI/npm; "tool shadowing" attacks |
| **Authentication/Authorization Gaps** | Medium-High | Misconfigured OAuth; weak delegation logic |
| **Tool Shadowing** | Medium | Malicious server weaponizes adjacent trusted servers |

### Defensive Measures Adopted
- Human-in-the-loop (HITL) for destructive/high-risk operations
- Least-privilege scoping for tool permissions
- **MCPInspect** — emerging tool for pre-integration audit of MCP servers
- **OWASP MCP Top 10** — currently in development

### Key Insight
> MCP cannot enforce security at the protocol level — security is an **implementation-level responsibility** requiring robust orchestration, strong identity boundaries, and continuous monitoring by the host application.

## 12. Google A2A Protocol & Anthropic/IBM ACP Protocol — Security Implications

### Google A2A (Agent-to-Agent Protocol)
- **Released:** April 2025; now governed by Linux Foundation
- **Purpose:** Enable AI agents across different frameworks/platforms to discover, authenticate, and coordinate
- **Auth mechanisms:** OAuth 2.0, API keys, mTLS

**Security Risks:**
- **Agent Card Vulnerabilities:** A2A uses "Agent Cards" (JSON at `/.well-known/agent.json`) for capability advertisement — malicious metadata can poison downstream agents
- **Identity Impersonation:** Malicious agents mimicking legitimate ones to infiltrate workflows
- **Fluid Trust Boundaries:** Machine-to-machine delegation → complex privilege escalation paths
- **Cascading Failures:** Compromise in one agent triggers domino effect across chained agents
- **Prompt Injection via Inter-Agent Messages:** Since agents act on configs/tools, injection = unauthorized data exfiltration or system modification

**Mitigations:**
- Security gateway for allowlisting, schema enforcement, OAuth validation on all inter-agent traffic
- Treat agents as "digital insiders" with enforced least-privilege policies
- Robust logging of all agent-to-agent interactions

### ACP (Agent Communication Protocol) — IBM/Linux Foundation
- **Not from Anthropic** — this is an IBM/Linux Foundation protocol (BeeAI project), separate from MCP
- **Purpose:** Standardized agent-to-agent communication and interoperability
- **Security features:** Cryptographic capability tokens limiting agent actions; Zero Trust posture

### The Full Protocol Stack (2026)
- **MCP (Anthropic):** Model ↔ Tool/Data source connections ("USB port for AI models")
- **A2A (Google/Linux Foundation):** Agent ↔ Agent coordination
- **ACP (IBM/Linux Foundation):** Agent ↔ Agent communication protocol (alternative to A2A)
- **Anthropic's Security Framework:** Zero Trust, OAuth 2.1, scoped access, trust escalation prevention
- These are **complementary**, not competing — modern enterprise stacks use all layers

## 14. New Attack Techniques Against LLMs & AI Agents (2025–2026)

### Established Techniques (Documented Pre-2025, Still Active)
| Technique | Status | Description |
|---|---|---|
| **Many-Shot Jailbreaking (MSJ)** | Highly active | Exploits large context windows; prepends many fake Q&A pairs to override safety alignment; follows power laws — more effective on larger models |
| **Crescendo** | Weaponized | Multi-turn, starts benign, gradually steers to prohibited content using model's own prior responses; "Crescendomation" tool automates it |
| **Skeleton Key** | Documented | Persuades model to revise its own behavior guidelines via "research context" framing; once agreed, model ignores guardrails |
| **"DAN" / Persona Attacks (incl. Grandma)** | Classic/baseline | Model adopts alternative persona to bypass safety; now considered "naive" — still used as component in compound attacks |

### New Techniques Emerged 2025–2026
| Technique | Discovered | Description |
|---|---|---|
| **Self-Jailbreaking** | 2026 | Reasoning/chain-of-thought models rationalize that unsafe requests are legitimate tests; jailbreak without external adversarial input |
| **Policy Puppetry** | 2025 | Attacker mimics structural formats (XML, JSON) to trick models into believing internal safety policies have been updated |
| **Thought Forgery (CoT Hijacking)** | 2025-2026 | Injecting fake reasoning artifacts into agent memory → biases future decisions, steers tool use for unauthorized actions |
| **Indirect Prompt Injection (Agentic)** | Now primary vector | Malicious instructions in documents/emails/websites processed by agents; agent treats it as trusted system context |
| **Skill Injection** | 2025 | Embedding malicious "skills" into agent tool registries to expand attack surface |
| **Ninja Attacks (Long-Context)** | 2025-2026 | Hiding harmful goals in large amounts of benign text; exploits model's attention bias toward beginning/end |
| **Echo Chamber / Context Poisoning** | 2025-2026 | Cumulative benign-sounding instructions across long conversations gradually erode safety guardrails |
| **Genetic Algorithm Prompt Evolution** | Active | Automated evolutionary optimization of jailbreak prompts using safety filter boundary feedback |
| **"AI Agent Clickbait"** (ATLAS) | 2026 | Crafted web/UI elements manipulating agent decision-making (formalized in MITRE ATLAS v5.4) |

### Defensive Innovations
- **LLM Salting:** Per-user random variations invalidate precomputed jailbreak strings
- **Recursive Detection (RLM-JB):** Secondary specialized model analyzes conversations for manipulation signs before primary agent acts
- **Neuron-level interpretability:** Reinforcing safety-critical neurons in model architecture
- **Continuous adversarial testing:** Automated quarterly red-team campaigns post model/system updates

## 15. AI Agent Memory / RAG Poisoning Research — 2026 State

### Threat Maturity: Theoretical → Active Exploitation (2026)

**Key distinction:** Unlike prompt injection (session-scoped), memory poisoning creates **persistent compromise** — corrupts long-term knowledge base, influencing decisions across future interactions.

### Core Attack Patterns

| Attack | Description | Documented Success Rate |
|---|---|---|
| **Memory Poisoning** | Plants malicious instructions in vector stores/conversation history; lies dormant until triggered by semantic context | 80–95% in agentic environments |
| **PoisonedRAG** | Small number of crafted documents manipulate AI responses; optimized for both retrieval AND generation | >90% (USENIX Security 2025) |
| **Embedding Inversion** | Inverting embeddings to recover sensitive source information → data leakage | Demonstrated in research |
| **Supply Chain RAG Poisoning** | Vulnerabilities in AI frameworks (LiteLLM, LangChain) used to inject poisoned content | Active exploitation in 2026 |
| **Cross-Tenant RAG Leakage** | Insufficient memory partitioning exposes data across users/tenants | Architecture flaw in many deployments |

### "RAG Trust Paradox" (Formally Named in 2025 Research)
> While user queries are treated as untrusted, data retrieved from RAG pipelines is frequently **implicitly trusted** by the agent — creating a fundamental architectural vulnerability.

### OWASP Coverage
- **LLM08:2025 — Vector and Embedding Weaknesses:** The 2025 OWASP list formally introduced this category, acknowledging vector databases and embedding pipelines as distinct, undertested attack surfaces

### Defensive Strategies (Current Best Practices)
1. **Memory Contracts:** Define what an agent is permitted to believe; enforce via configuration
2. **Memory Sanitization + Provenance Tracking:** Track source of every piece of information in memory
3. **Context Isolation & Partitioning:** Prevent cross-tenant data leakage; least-context access
4. **Trust-Aware Retrieval:** Verification layer validates retrieved document integrity before injection into context
5. **Behavioral Monitoring / "Belief Drift" Detection:** Monitor for anomalous decision-making patterns suggesting compromise
6. **Framework Auditing:** Regular audits of LangChain, LiteLLM, and other AI framework dependencies for supply chain poisoning
